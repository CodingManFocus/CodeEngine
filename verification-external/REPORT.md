# Plugin API verification report

The final implementation was tested against the real, free PlaceholderAPI 2.11.6 on Paper 1.21.11 build 132 with normal Paper plugin remapping. ItemsAdder was not installed or tested.

## Evidence availability

The source and verification harness were saved in commit `467511e014c56069f48e83bf04ab301277792535` before the execution environment disconnected. The completed final run's exact summary was recovered from already printed execution output and is preserved in [results/final/summary.json](results/final/summary.json). **Raw sample CSVs, server logs, generated bytecode listings and the original environment/source manifests could not be uploaded after the disconnect. They are not included in this PR.** No raw samples have been reconstructed or invented. The [reproduction instructions](README.md) and harness are included so the complete evidence can be generated again.

## Scope that differs from a native plugin

`requires plugin` does not add a Paper dependency edge or give each module its own Plugin identity. Even an ordinary server stop can disable the provider before CodeEngine, in which case the module's `disable` and `onClose` hooks are skipped. The normal-stop probe observed exactly this behavior. Explicitly unload modules while their providers remain active when cleanup must run. Do not use these shutdown hooks as the only durable save.

Support is limited to Bukkit `plugin.yml` JavaPlugin providers with supported local JAR layouts. Paper-plugin providers, nested API loaders, provider hot replacement and independently owned Plugin identities are not supported. Arbitrary external asynchronous callbacks are not automatically tracked. Keeping a generated module JAR open until admitted code returns does not guarantee arbitrary API execution after the engine or provider itself stops.

The paired delta is the median of within-tick differences. It is not the difference between the two independent medians, so mixed signs between those two summaries are possible. The exact per-fork p95 batch means and median ratios are retained in the JSON summary; those p95 values are neither individual-call nor server-tick percentiles.

Direct API paired median differences ranged from -8.75 to +3.55 ns/op across the six workload/fork combinations. The full command path had positive paired median differences in all three forks: +61.38, +27.58 and +18.39 ns/op. This includes the engine's admission/drain bookkeeping. **All 2,160 measured native/module batch pairs allocated exactly the same number of bytes.** The API itself allocates; the measured additional allocation was zero.

These measurements support a small observed direct-call cost and small command tracking cost for these workloads. They do not establish universal equivalence, zero overhead, a maximum latency, or multiplayer TPS. The lifecycle tracking was retained rather than weakened to improve a microbenchmark.

Six full module compile/load operations in each final JVM took 186.8–251.8 ms overall. This includes javac, dependency indexing, scheduling and activation. JVM/compiler/OS caches are warm across repeated loads. It is separate from steady-state API execution and is not comparable to starting a precompiled Java plugin.

## Findings and corrections

- The pilot exposed different command allocation totals because the command names had different lengths. The final harness uses equal-length `javapapi` and `codepapi` names.
- The engine-disable-hook fixture initially expected a pending unload to succeed after engine shutdown. Its assertion was corrected to expect a failed pending operation, separately from the production lifetime fixes.
- A shutdown probe exposed parent-first lookup of a newly used generated inner class through Paper's already closed engine loader. Generated classes now use an exact own-JAR class index and verified origin, with collision rejection. Declared provider types still use the provider's actual loader.
- Engine shutdown inside activation exposed missing ownership of an in-progress candidate and construction of disposal state after the engine loader closed. The same lifetime carrier is now registered before class initialization or user constructors/hooks. An activation guard keeps artifacts owned until the call returns; shutdown transfers that ownership before Paper closes the engine.
- Managed commands and timers now participate in the existing drain mechanism, so reentrant provider stop does not close their module JAR before their admitted call returns.
- Every provider-sensitive cleanup is guarded; resource cleanup runs in reverse order, continues across individual failures, and does not call into a provider already marked stopped.
- An initial legacy regression failure was traced to external workspace synchronization restoring source files after the engine deleted a build directory. The unchanged final engine passed in a fresh `/tmp` server directory. Final timing forks also used `/tmp` to avoid this interference.
- After these corrections, the five shutdown probes, existing regression suite and all three final timing forks passed. No plugin-loader internals, runtime dependency graph mutation, forced class preloading or per-API-call reflection was introduced.
